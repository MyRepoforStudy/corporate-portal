# Загрузка справочника сотрудников

Источник данных — Excel-справочник HR («Справочник Сотрудников …xlsx»). На сайт он попадает через CSV: конвертер готовит файл, а загрузка выполняется в админ-панели.

## Как загрузить

1. Конвертация (нужен только Python 3):

```bash
python scripts/directory-to-csv.py "Справочник Сотрудников BNK Bank_2026.xlsx" "C:\Users\USER\Documents\bnk-directory-import.csv"
```

Скрипт печатает отчёт: сколько людей, подразделений и должностей, что исправлено автоматически и какие строки не попали в CSV.

2. Админ-панель → «Импорт» → выбрать CSV → «Импортировать». Миграция БД (колонка `location`) должна быть уже применена.
3. Открыть «Оргструктуру» и проверить результат.

## Что делает конвертер

- **Подразделения.** «Категория → Структурное подразделение → отдел/управление» превращается в иерархию. Первая категория (руководство банка) становится единым корнем **«Правление»**: председатель и заместители сидят прямо в нём, а остальные категории и «Главный бухгалтер», «Руководитель ИТ» — его дочерние блоки (так оргструктура выглядела на сайте раньше). Пустые ячейки объединённых областей Excel разворачиваются. Флаг `--no-root` оставляет каждую категорию отдельным узлом верхнего уровня, `--no-categories` убирает уровень «Категория» совсем.
- **Локация.** `2/левое крыло` → «2 этаж, левое крыло», `ШФ` → «Шымкентский филиал». `0` и пустая ячейка считаются «не указано» и в карточке не показываются (`--keep-zero-location` оставит «0 этаж»).
- **Ранг должности** (старшинство) ставится по названию, правила в `RANK_RULES` в начале скрипта. По рангу определяется руководитель подразделения и порядок сотрудников. Ранг можно поправить в «Админ → Должности».
- **Исправления** выводятся в отчёт: опечатка в домене e-mail (близкая к основному домену) и известные опечатки в должностях (`POSITION_FIXES`).
- **Дубли e-mail.** В БД e-mail уникален, поэтому второй человек с тем же адресом в CSV не попадает. Конвертер перечисляет такие строки: исправьте адрес в Excel и запустите скрипт снова.

## Формат CSV

Колонки: `fullName`, `email`, `position`, `position_rank`, `department_path`, `location`. Импорт принимает также `phone`, `birthDate`, `hireDate` (ГГГГ-ММ-ДД) и колонку `department` вместо `department_path`.

## Повторная загрузка

- Сотрудник ищется по e-mail без учёта регистра: существующий обновляется (ФИО, подразделение, должность, локация), новый создаётся. Пустые поля файла (телефон, даты, локация) уже сохранённые данные не стирают.
- Новые подразделения встают в том порядке, в котором идут в файле.
- Импорт **ничего не удаляет**. Демо-записи из seed и уволенных сотрудников убирайте вручную: «Админ → Сотрудники → Удалить выбранных», затем ненужные подразделения.

## Однократно: заменить старое дерево «Правление»

Если до загрузки справочника на сайте уже была старая структура «Правление», после импорта она остаётся рядом с новыми блоками. Скрипт `scripts/restructure-board.sql` удаляет старое дерево вместе с его сотрудниками и собирает новую структуру под единым корнем «Правление». У совпавших по ФИО людей телефон, фото и даты из старых карточек переносятся в новые (в справочнике их нет), учётные записи входа перепривязываются. Вакансии переносятся в одноимённое подразделение нового дерева (если оно ровно одно), остальные пропадают: сколько именно, видно в отчёте репетиции.

Скрипт рассчитан на состояние, когда загружен CSV, подготовленный с флагом `--no-root` (10 блоков верхнего уровня). **Не импортируйте CSV с корнем «Правление» до скрипта**: он влился бы в старое дерево. Скрипт сам останавливается и ничего не меняет, если новой структуры нет, она неполная или скрипт уже выполнялся.

1. Бэкап базы:

```bash
docker compose exec -T postgres pg_dump -U portal -Fc corporate_portal > backup_$(date +%F).dump
```

2. Репетиция: всё выполняется и откатывается, на экран выводится отчёт (сколько подразделений и людей удалится, кто останется без тёзки в новом дереве):

```bash
docker compose exec -T postgres psql -U portal -d corporate_portal -v ON_ERROR_STOP=1 < scripts/restructure-board.sql
```

3. Применение (тот же запуск с флагом `apply`):

```bash
docker compose exec -T postgres psql -U portal -d corporate_portal -v ON_ERROR_STOP=1 -v apply=1 < scripts/restructure-board.sql
```

4. После этого для повторных загрузок используйте CSV стандартного формата (с корнем «Правление»): он совпадает с получившейся структурой.

## Персональные данные

И Excel, и CSV содержат персональные данные. В репозиторий они не попадают (`*.xlsx` и `directory-import*.csv` в `.gitignore`), храните их вне проекта и удаляйте CSV после импорта.
